# TxtJPEG-C 设计文档

## 1. 系统架构

```
┌─────────────┐     ┌──────────────┐     ┌───────────────┐
│  input.txt  │────▶│  parser.c    │────▶│  float* values │
└─────────────┘     └──────────────┘     └───────┬───────┘
                                                 │
                                                 ▼
┌─────────────────────────────────────────────────────────────┐
│                     Compress Pipeline                        │
│  1. format.c 推断原始格式模板 (%9.2f,)                       │
│  2. parser.c 流式解析 → float*                               │
│  3. normalize.c 统计并线性归一化到 uint8*                    │
│  4. shape.c 确定二维图像尺寸（8 的倍数）                     │
│  5. jpeg_codec.c 编码灰度 JPEG                               │
│  6. container.c 写入 .tj 容器                                │
└─────────────────────────────────────────────────────────────┘
                                                 │
                                                 ▼
                                          ┌──────────────┐
                                          │   output.tj  │
                                          └──────┬───────┘
                                                 │
┌─────────────────────────────────────────────────────────────┐
│                     Decompress Pipeline                      │
│  1. container.c 读取 .tj 头部和 JPEG 数据                    │
│  2. jpeg_codec.c 解码 JPEG 为 uint8*                         │
│  3. normalize.c 反映射回 double*                             │
│  4. format.c / decompress.c 按模板格式化输出                 │
│  5. 按 columns 恢复换行                                      │
└─────────────────────────────────────────────────────────────┘
```

## 2. 模块设计

### 2.1 `compat.h`

兼容性头文件，封装 VS2013 缺失的 C99 特性：

- `tjpeg_snprintf`：在 VS2013 下调用 `_vsnprintf_s`，其他平台调用 `snprintf`。
- `TJ_INLINE`：映射为 `__inline`（MSVC）或 `inline`（GCC/Clang）。
- `TJ_RESTRICT`：映射为 `__restrict` 或 `restrict`。
- 自定义 `bool` 类型（`int` + `true/false` 宏），避免依赖 `stdbool.h`。

### 2.2 `txtjpeg.h`

公共头文件，定义：

- `TJPEG_MAGIC`、`TJPEG_VERSION`、`TJPEG_HEADER_SIZE`
- `tj_container_t`：完整 `.tj` 容器结构。
- `tj_data_t`：解析后的浮点数据集。
- 压缩/解压入口函数声明。

### 2.3 `parser.c`

流式浮点解析器，核心设计：

- 1 MiB 分块读取。
- 维护 `carry` 缓冲区处理跨边界 token。
- 使用 `strtod` 转换浮点数。
- 同步统计 `vmin`、`vmax`。
- 在首块中采样推断 `columns`。

### 2.4 `format.c`

原始格式推断：

- 读取文件前 4 KiB。
- 找到第一个逗号，计算 token 宽度和精度。
- 生成类似 `%9.2f,` 的格式字符串。

### 2.5 `shape.c`

二维尺寸计算：

- 自动模式：`w = ceil(sqrt(N))`，向上对齐到 8；`h = ceil(N / w)`，向上对齐到 8。
- 显式模式：解析 `--shape HxW`，再分别对齐到 8。

### 2.6 `normalize.c`

线性映射：

- 压缩：`pixel = round((v - vmin) / (vmax - vmin) * 255)`，并裁剪到 0–255。
- 解压：`value = pixel / 255 * (vmax - vmin) + vmin`。
- `vmin == vmax` 时统一输出 `vmin`。

### 2.7 `jpeg_codec.c`

libjpeg 封装：

- 编码：使用自定义内存目标管理器，把灰度图编码到内存缓冲区。
- 解码：使用 `jpeg_mem_src` 从内存读取并解码。
- 错误处理：通过 `setjmp/longjmp` 捕获 libjpeg 错误。

### 2.8 `container.c`

`.tj` 容器读写，采用显式小端序字节操作：

- `read_u16_le`、`read_u32_le`、`read_u64_le`、`read_f64_le`
- `write_u16_le`、`write_u32_le`、`write_u64_le`、`write_f64_le`
- 保证在不同平台（x86、ARM）上字节序一致。

### 2.9 `compress.c` / `decompress.c`

流程编排模块，把上述模块按顺序组合，输出统计信息。

### 2.10 `main.c`

命令行入口：

- 解析 `compress` / `decompress` 子命令。
- 处理 `--quality`、`--shape` 选项。
- 记录并输出耗时。

## 3. 容器格式（与 Python 版一致）

| 字段 | 类型 | 长度 | 说明 |
|------|------|------|------|
| Magic | bytes | 8 | `TXTJPEG\0` |
| Version | uint8 | 1 | 2 |
| Quality | uint8 | 1 | 1–100 |
| Width | uint32 | 4 | 图像宽度（小端序） |
| Height | uint32 | 4 | 图像高度（小端序） |
| N | uint64 | 8 | 浮点个数 |
| vmin | float64 | 8 | 最小值 |
| vmax | float64 | 8 | 最大值 |
| columns | uint32 | 4 | 每行 token 数，0 表示无换行 |
| fmt_len | uint16 | 2 | 格式字符串长度 |
| fmt_str | bytes | fmt_len | 如 `%9.2f,` |
| jpeg_len | uint64 | 8 | JPEG 数据长度 |
| jpeg_data | bytes | jpeg_len | 标准灰度 JPEG |

## 4. 内存管理

| 阶段 | 主要分配 |
|------|----------|
| 解析 | `float* values`（4 字节/值） |
| 归一化 | `uint8_t* pixels`（宽高积） |
| JPEG 编码 | 内部临时缓冲 + 输出 `jpeg_data` |
| JPEG 解码 | `uint8_t* gray`（宽高积） |
| 反映射 | `double* values`（8 字节/值） |

所有分配都有对应 `free`，避免泄漏。

## 5. 跨平台适配

| 平台 | 构建方式 | 注意事项 |
|------|----------|----------|
| Linux | `make` | 链接 `-ljpeg`，加 `-lm` |
| macOS | `make` | 可用 Homebrew 安装 jpeg-turbo |
| Windows MSYS2 | `mingw32-make` | 得到原生 Windows exe |
| Windows VS2013 | 新建空项目或 CMake | 需手动提供 libjpeg-turbo |

## 6. VS2013 特殊处理

为兼容 VS2013，代码中避免使用以下 C99 特性：

- `for (int i = 0; ...)` → 改为 `int i; for (i = 0; ...)`
- 块中间声明变量 → 全部移到块首
- `snprintf` → 封装为 `tjpeg_snprintf`，VS2013 内部调用 `_vsnprintf_s`
- `inline` / `restrict` → 通过宏映射为 `__inline` / `__restrict`
- `getopt_long` → 自定义命令行解析循环

## 7. 测试验证

建议测试流程：

1. C 版与 C 版：压缩后解压，对比行数、列数、格式。
2. C 版与 Python 版：互相压缩/解压，验证容器可互读。
3. 用 `compare.py` 计算误差，确认与 Python 版同一 quality 下误差接近。
