# TxtJPEG-C 方案文档

## 1. 目标

把 Python 版 TxtJPEG 的核心能力用 C 语言重新实现，满足以下诉求：

1. **格式兼容**：生成的 `.tj` 文件与 Python 版互相可读可写。
2. **跨平台**：支持 Linux、macOS、Windows，并能在 VS2013 这类老编译器上编译。
3. **性能提升**：减少 Python 对象和解释器开销，解析与格式化阶段显著提速。
4. **部署简单**：最终只需要一个可执行文件加一个 JPEG 动态库。

## 2. 核心思路

与 Python 版保持一致：

```
文本浮点数  →  float32 数组  →  uint8 灰度像素  →  二维图像  →  JPEG 有损压缩  →  .tj 容器
```

关键选择：

- **libjpeg / libjpeg-turbo**：负责 JPEG 编码解码。libjpeg-turbo 带 SIMD 优化，速度更快。
- **纯 C 数组**：替代 numpy，手动管理 `float*`、`uint8_t*`、`double*`。
- **流式解析**：仍按 1 MiB 分块读取文本，避免一次性加载大文件。
- **C89/C90 代码风格**：兼容 VS2013，避免 C99 特性。

## 3. 运行方式

编译后得到 `txtjpeg`（Linux/macOS）或 `txtjpeg.exe`（Windows）：

```bash
txtjpeg compress input.txt output.tj --quality 85
txtjpeg decompress output.tj output_approx.txt
```

参数与 Python 版一致：

- `--quality N`：JPEG 质量，1–100，默认 85。
- `--shape HxW`：显式指定二维形状，例如 `10000x5789`。

## 4. 与 Python 版的差异

| 方面 | Python 版 | C 版 |
|------|-----------|------|
| 依赖 | numpy、Pillow | libjpeg/libjpeg-turbo |
| 运行方式 | `python txtjpeg.py ...` | `txtjpeg ...` |
| 内存管理 | Python 垃圾回收 | 手动 malloc/free |
| 代码风格 | Python 3 | C89（兼容 VS2013） |
| 容器格式 | 相同 | 相同 |
| JPEG 数据 | 标准灰度 JPEG | 标准灰度 JPEG |

## 5. 性能预期

在 Python 版测过的 579 MB 样例文件上，C 版预期表现：

| 阶段 | Python 耗时 | C 版预期耗时 |
|------|-------------|--------------|
| 解析浮点 + 统计 min/max | ~5 s | ~1–2 s |
| JPEG 编码 | <1 s | <0.5 s |
| 解压 + 格式化输出 | ~6 s | ~2–3 s |

主要提升来自：

- 没有 Python float 对象的创建与销毁。
- 格式化输出用 `snprintf` 直接写缓冲区，避免 Python 字符串拼接。
- 数值数组在 native 内存中连续存放，缓存友好。

## 6. 兼容性保证

为确保 C 版与 Python 版互操作：

1. `.tj` 容器头部字段顺序、类型、字节序完全一致。
2. JPEG 编码参数一致：灰度图、quality、optimize_coding。
3. 归一化公式一致：`pixel = round((v - vmin) / (vmax - vmin) * 255)`。
4. 反映射公式一致：`value = pixel / 255 * (vmax - vmin) + vmin`。
5. 格式模板推断逻辑与 Python 版一致。
6. 列数推断逻辑与 Python 版一致。

## 7. 局限与注意事项

- 同样是有损压缩，不适合需要精确还原的场景。
- 大文件会一次性把所有浮点数读入内存（`float*` 约 4 字节/值）。
- VS2013 下需要显式配置 libjpeg-turbo 的 include/lib/dll。
- Windows 下必须使用二进制模式（`"rb"` / `"wb"`）打开文件。

## 8. 下一步可扩展

- 用 libjpeg-turbo 的 TurboJPEG API 进一步提速。
- 增加进度条输出。
- 支持多线程并行解析超大文件。
- 增加非线性归一化（如对数映射）。
